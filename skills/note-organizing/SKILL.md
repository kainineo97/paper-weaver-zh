# Note Organizing Skill

## Overview

这个 skill 专门用于整理笔记、整理文章、整理资料、课堂/讲座/会议笔记整理，以及把转写稿、访谈、播客、会议记录或零散材料整理成清楚、忠实、可复习、可沉淀的中文笔记。

它不是公众号成稿 skill。整理笔记的重点是还原材料逻辑、清理噪音、提炼主题、合并相近观点、保留关键细节和原文依据；不是强行制造标题冲突、公众号钩子或个人判断。

关键原则：忠实优先，主题合并其次，结构清晰再次。默认不要输出大段连续正文，而是输出“主题标题 + 核心要点 + 展开阐述 + 原文引用与说明”的要点式知识笔记。可以根据上下文修正明显错字和口误，但不要凭空添加材料中没有的信息。

## When to Use

使用此 skill，当用户说：

- “整理笔记”
- “整理文章”
- “整理资料”
- “提炼文章”
- “整理课堂笔记”
- “整理会议纪要”
- “把这段转写整理一下”
- “整理成可读笔记”
- “把文件夹里的材料整理成笔记”
- “把讲座/课程/访谈内容整理成结构化笔记”

不要使用此 skill，当用户明确说：

- “写公众号文章”
- “写成能发布的文章”
- “写一篇有传播感的文章”
- “写成人人都是产品经理风格文章”

这些场景应使用 `article-writing`。

## Output Modes

根据用户表达选择输出模式。默认优先使用“主题合并型要点笔记”。

### 模式一：主题合并型要点笔记（默认）

适用于课堂、讲座、会议、转写稿、资料复习、文章整理和知识库沉淀。

核心流程：先通读原始材料，列出所有主题、观点、概念和反复出现的问题；再把语义相近、重复、同类、前后呼应的内容合并成几个大主题；最后围绕每个大主题输出“标题 + 要点 + 阐述 + 引用说明”。

推荐结构：

```markdown
# 标题

## 一、主题标题

### 核心要点
- 要点一：……
- 要点二：……
- 要点三：……

### 展开阐述
基于原笔记的表达方式，把这个主题背后的逻辑、关系、原因、例子讲清楚。语言可以修顺，但不要改成通用 AI 腔，也不要加入原材料没有的判断。

### 原文引用与说明
> “……”

说明：这句话是本节主题的核心依据，说明了……
```

格式要求：每个大主题完成后只加一个空行，再进入下一个大主题；不要整篇到处堆空行。标题、三级小标题、要点列表、阐述段落、引用说明之间保持必要空行即可，避免看起来松散怪异。

完成标准：读者不看原文，也能知道材料讲了什么、主题之间如何归类、哪些观点被合并了、每个主题的原文依据是什么。

### 模式二：整理文章样稿

适用于用户说“整理文章”“文章样稿”“按整理文章格式”，但没有要求写成公众号成稿。

仍然使用主题合并型结构，不要写成连续段落式文章。每个大主题包含：

1. 主题标题：用一句能概括该组内容的标题命名。
2. 核心要点：用 bullet 列出这一主题下的关键观点。
3. 展开阐述：基于原笔记的表达方式，把逻辑和关系讲清楚。
4. 原文引用与说明：每个大主题末尾放 1-3 条最能支撑本节的原文引用，并用一句说明解释它为什么支撑本主题。

完成标准：结构清晰、逻辑完整、同类内容已合并，能复用到后续写文章或知识库沉淀，但不会误写成公众号成稿。

### 模式三：清洗型笔记

适用于用户明确说“只清洗，不分段 / 不总结 / 不改结构”。

只做：

- 去除时间戳
- 去除重复语句
- 去除口头语
- 去除明显噪音
- 修正明显转写错误
- 清理乱码、不可见字符、多余空行
- 保留原文顺序和原有结构

不做：

- 不做语义分段
- 不压缩成摘要
- 不公众号化
- 不强行添加标题冲突
- 不凭空补充材料

完成标准：内容更干净，但仍然能看出原始材料的顺序和信息。

## Processing Workflow

1. 读取材料。
   完成标准：已读取用户指定的文本、Markdown、Word、转写稿或文件夹中的可读材料；遇到 `.doc` 等旧格式时，在 macOS 上可用 `textutil -convert txt -stdout <文件路径>` 抽取正文。

   多文件课程/讲座材料补充：如果用户给的是同一课程、同一天或同一主题下的多个转写文件，并要求“整理笔记”而不是“每个文件分别整理”，默认合并成一份综合课程笔记；章节按主题重组，而不是机械按文件名逐篇摘要。只有用户明确要求“每个文件一份笔记”时，才分别输出。

2. 判断用户要的是哪种整理。
   完成标准：区分“主题合并型要点笔记 / 整理文章样稿 / 只清洗 / 公众号成稿”。如果用户明确要公众号成稿，切换到 `article-writing`。

3. 清理噪音。
   完成标准：去掉时间戳、无意义口头语、重复句、明显转写噪音和不可见字符；不删除有信息量的内容。

4. 列出全部主题。
   完成标准：从原材料中识别所有出现过的主题、观点、概念、问题、案例和反复出现的表达；不要边看边直接写成流水账。

5. 合并语义相近主题。
   完成标准：把相同意思的不同表述、同一问题下的分散内容、前后呼应的观点、围绕同一案例或概念的材料合并成一个大主题；不要把重复观点拆成多个章节。

6. 基于原笔记表达重写。
   完成标准：语言更清楚顺滑，但保留原笔记里的判断方式、关键词、比喻、语气和有价值表达；不要改成模板化 AI 摘要、商业黑话或“首先其次最后”的机械结构。

7. 为每个大主题补充引用与说明。
   完成标准：每个大主题末尾都有“原文引用与说明”；引用少而准，通常 1-3 条即可；每条或每组引用后用一句简洁说明解释它如何支撑本节主题。

8. 输出可读 Markdown。
   完成标准：标题清楚，层级合理；默认要点式结构；每个大主题完成后只加一个空行，不要整篇堆空行；如果用户要求紧凑格式，则进一步减少空行和列表。

## Style Rules

- 中文为主。
- 默认输出“主题标题 + 核心要点 + 展开阐述 + 原文引用与说明”。
- 整理课堂、讲座、培训转写稿时，目标是梳理重点和知识结构，不是写评论文章，也不是逐句翻译原文。
- 默认不要写成大段连续正文，也不要写成段落式 AI 总结。
- 先列出所有主题，再合并语义相近主题，最后按大主题组织输出。
- 相同观点、相同主题、相同问题下的内容必须合并，不要重复铺开。
- 整合型笔记要把同一主题下分散出现的材料揉成一个完整知识块；不要把原文拆成很多孤立小点，也不要一条引用配一条解释地机械排列。
- 多级标题要承担结构功能：二级标题放大主题，三级标题放关键知识块，四级标题只在确实需要细分流程/维度时使用。
- 阐述要按分标题展开，长短跟随原文信息量；信息密集处要写细，不能为了简洁遗漏知识点。
- 原文依据要优先自然嵌入对应阐述段落里，用来支撑当前知识块；不要默认在每节末尾单独堆“原文引用与说明”。
- 引用不用多，少而准；引用后要顺势解释它支撑了什么知识点，避免孤立贴原文。
- 要基于原笔记的表述方式整理，尽量保留原笔记的关键词、判断、比喻和语气。
- 可以修顺句子，但不要改变原意。
- 遇到明显转写错误，可以根据上下文修正；不确定时不要乱改。
- 不要写成过度 AI 化的摘要。
- 不要把所有信息平均摊开，要抓住真正重要的主题。
- 但也不要过度压缩到丢失材料细节。
- 保留原文里有价值的案例、场景、概念、金句。
- 默认 Markdown。
- 格式要紧凑：每个大主题结束后只留一个空行，不要整篇都是空行。
- 如果是文章整理正文，段落顶格，不要段首缩进。
- 不要为了显得高级而硬加商业、AI、产品判断；材料里有什么，就从材料里提炼什么。

## Common Pitfalls

1. 把整理笔记写成公众号文章。
   修正：整理笔记要忠实、清楚、可复习，不需要强标题、强钩子和传播感。

2. 写成纯段落式 AI 总结。
   修正：默认使用“主题标题 + 核心要点 + 展开阐述 + 原文引用与说明”的要点式结构。

3. 只按原文顺序流水整理。
   修正：先列出全部主题，再合并语义相近内容，最后按大主题重组。

4. 把相同观点拆成多个主题。
   修正：相同意思的不同说法、前后呼应的内容、同一问题下的分散材料，都合并到同一个大主题里。

5. 把原文压缩得太狠。
   修正：保留关键案例、概念、步骤、论证链和原文金句。

6. 擅自扩写材料没有的判断。
   修正：可以归纳，但判断必须能从原文推出。

7. 引用堆太多。
   修正：每个大主题保留 1-3 条最有代表性的引用即可，并补一句说明。

8. 引用没有解释。
   修正：引用后必须说明它如何支撑该主题，不能只贴原文。

9. 改写得失去原笔记语气。
   修正：修顺句子，但尽量保留原笔记的关键词、判断方式、比喻和表达习惯。

10. 空行过多导致版面松散。
    修正：每个大主题结束后只加一个空行，不要整篇到处空行。

11. 遇到 Word / doc 文件直接放弃。
    修正：在 macOS 上先用 `textutil` 转文本，再整理。

12. 用户说“不需要语义分段”却重排内容。
    修正：清洗型笔记只清洗，不重新组织结构。

13. 过度保留口头语。
    修正：去掉“嗯、啊、然后呢、就是说、这个、那个、对吧”等无信息量表达，但保留真实观点。

## Verification Checklist

完成前检查：

- [ ] 已判断输出类型：主题合并型要点笔记 / 整理文章样稿 / 清洗型笔记 / 整合型课堂笔记。
- [ ] 没有误写成公众号成稿；如果用户明确要公众号，已切换 skill。
- [ ] 内容忠实原文，没有编造材料外信息。
- [ ] 已去除明显噪音、时间戳、重复句和无意义口头语。
- [ ] 已先识别全部主题，再合并语义相近主题。
- [ ] 相同观点没有被拆成多个章节重复铺开。
- [ ] 默认结构下，每个大主题都有：主题标题、核心要点、展开阐述、原文引用与说明。
- [ ] 整合型课堂笔记下，原文依据已嵌入对应阐述里，没有单独堆到文末。
- [ ] 整合型课堂笔记下，使用多级标题梳理知识块，阐述解释详实且长短随原文信息量。
- [ ] 每个大主题末尾都有引用，且引用少而准；若采用整合型结构，则引用已自然分布在对应阐述中。
- [ ] 引用后有解释说明，不是孤立堆原文。
- [ ] 语言贴近原笔记表达方式，没有改成模板化 AI 腔。
- [ ] Markdown 层级清晰，整体格式紧凑。
- [ ] 每个大主题结束后只留一个空行，没有整篇堆空行。
- [ ] 如果用户要求“不分段 / 只清洗”，没有擅自重排结构。
- [ ] 如果处理文件夹，已说明成功、跳过和失败文件；除非用户允许，不额外生成报告文件。
