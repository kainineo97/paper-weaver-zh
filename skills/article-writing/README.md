# Article Writing Skill

这是一个用于中文长文写作的 Hermes Agent Skill，适合将观点、笔记、访谈、播客、会议记录、录音转写或资料摘录，转化为可继续打磨发布的文章成稿。

该 skill 产出的文章已被「人人都是产品经理」收录。

## Skill 定位

这个 skill 不是普通摘要工具，也不是会议纪要模板。它更适合处理“我要把材料写成一篇文章”的场景：需要标题、开篇钩子、中心判断、论证链、案例支撑和完整结尾。

它强调的是文章成稿能力，而不是资料压缩能力。用户给出的原文、大纲、笔记或简述稿，只是素材和方向，不是正文模板。写作时需要重新组织开场判断、材料顺序、案例位置和论证节奏，让文章读起来像一篇完整原创文章。

## 适用场景

- 公众号文章写作
- 人人都是产品经理风格的产品/商业观点文章
- AI、产品、商业、组织、个人成长等中文长文
- 从访谈、播客、会议记录、录音转写中生成文章
- 将碎片观点、笔记、大纲扩展成可读成稿
- 对已有文章进行结构重组和表达升级

## 不适用场景

- 极短摘要
- 会议纪要
- 课堂笔记
- 原文提纲
- 资料清洗
- 社媒短帖
- PRD 或技术文档

如果目标只是“整理资料”或“做笔记”，应该使用笔记整理类 skill，而不是这个文章写作 skill。

## 核心写法

这个 skill 默认遵循以下文章推进链条：

```text
中心论点
→ 核心冲突
→ 为什么成立
→ 案例 / 材料支撑
→ 旧认知或旧方案的局限
→ 新判断 / 新机会 / 新启发
```

文章不应该按原材料顺序平铺，也不应该把用户大纲机械扩写。真正重要的是先识别文章的中心冲突，再围绕这个冲突重组材料。

## 输出风格

- 中文 Markdown 正文
- 标题要有判断和冲突，不做中性概括
- 开篇三段内进入核心问题
- 正文以自然段落推进，少用清单
- 段落顶格写，段首不缩进
- 避免“首先、其次、最后”“综上所述”等模板句
- 不编造材料中没有的事实
- 结尾要完成判断，而不是简单复述全文

## 文件说明

- `SKILL.md`：Hermes Agent 可加载的 skill 主文件
- `README.md`：当前 skill 的说明文档

## 使用方式

在支持 Hermes Skill 的环境中加载 `SKILL.md`，或将 `SKILL.md` 作为写作 Agent 的上下文提示词使用。

典型使用方式：

```text
请使用 article-writing skill，把以下材料写成一篇可发布的中文文章。
目标平台：公众号 / 人人都是产品经理。
要求：标题有冲突，开篇直接进入核心判断，正文有案例支撑，不要写成摘要。
```

如果有本地素材文件，应该先读取素材，再开始写作。不要在没有读取材料的情况下凭空补事实。

## 验证清单

写完文章前，至少检查：

- 标题是否有明确判断或冲突
- 开篇三段内是否出现核心问题
- 正文是否围绕一个中心论点推进
- 是否至少有一个具体案例或材料细节支撑主要判断
- 是否避免了机械大纲式表达
- 是否没有编造原文不支持的事实
- 结尾是否把文章收束到更高层判断
