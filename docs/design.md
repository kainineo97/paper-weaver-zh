# Paper Weaver 的组合设计

这是助手驱动的科研编辑流程。论文提供证据，讨论提供需要回应的问题，文章则按读者理解所需的顺序展开。脚本不理解论文，也不会自行完成写作或科学批准。

## 三份材料，三种职责

| 中间材料 | 职责 |
|---|---|
| discussion map | 合并重复追问，记录问题覆盖和延后原因 |
| story map | 决定中心问题、章节功能、证据位置与节间承接 |
| claim ledger | 约束关键数字、事实和推论的来源、条件及结论强度 |

paper facts 另行逐篇保留实验设计、结果、局限与页码。多论文可以围绕共同问题成文，但不能抹掉研究间的物种、时点、分母或重复层级差异。

## 四条泳道，不是四个代理

图中用户负责提供材料与审阅；脚本负责归档、检查和渲染；助手的理解写作与复核定稿分列两条泳道，是为了说明职责。实现并不要求多代理架构。

主线为材料归档 → 问题与证据 → 叙事与初稿 → 全文润色 → 科学复核 → 定稿及审核记录 → 结构版本检查 → 渲染 → 本地交付。普通顺序箭头不重复标注端点已表达的交接；通过、需修正和重新润色保留语义标签。

## 两道门不能互相替代

科学复核要回到论文，检查润色是否改变数字、肯否定、比较对象与因果强度。失败后修订受影响的内容，重新润色并复核。

结构与版本检查只核对来源文件、账本、引用、审核记录和当前文件指纹。它不能自动判断科研结论真假。图中未穷举结构失败分支；实际执行应按诊断处理，涉及被审核材料的改动需重新复核。

最终审核指纹覆盖正文、语义元数据与图片，所以标题、摘要、封面和图注必须先就绪。0.1.1-fork 已将这一顺序写入入口和复核规则；后续改变内容不能只刷新指纹。

## 组合而不重复实现

note-organizing 做内部讨论整理，article-writing 提供结构与成稿能力，humanizer-zh 做全文中文编辑；ReoNa 提供科研约束及工具链，reona-paper-digest-zh 提供同步页面。依赖作为独立目录随包提供。paper-weaver 只承担阶段串联、证据追溯与审核约束。

默认完成点是本地阅读页与富文本复制页。上传微信草稿需要另行请求，公开发布由用户操作。软件校验、页面显示校验和科学复核的证据应分别记录，不相互冒充。
